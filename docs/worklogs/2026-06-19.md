## 1. Render-SATB Task 2 — bridge `render_satb` orchestrator (`app/bridge.py`)
Additive, 4 new methods after `reveal` (no other code touched):
- `render_satb(stems_path)` — async js_api entry; spawns the worker off-thread so
  the UI never blocks.
- `_render_satb_worker` — extracts the **L (melody)** channel from the stereo
  `take_*_stems.wav` into a temp mono `<take>_melody.wav` (the `--render` path
  averages all input channels, so we must isolate melody), then renders each
  *active* `SATB_VOICES` part **solo** (`--no-you`) → `<take>_satb_<part>.wav`, and
  one full mix (active + You) → `<take>_satb.wav`. Streams
  `window.onRenderStatus` (rendering/done/failed).
- `_render_once` — one `--render` subprocess per call.
- `_push_render_status` — the status push (mirrors `_push_saved`).

### Key/scale correctness fix (caught at verify)
The plan's `_render_once` passed only `--render/--model/--voices`, so every render
ran at the **engine default C major** regardless of the take's key — the diatonic
harmony would be wrong for any non-C take. Fixed: `_render_once` now also passes
`--key/--minor` from `self.control`. Takes store **no key metadata** (confirmed: the
engine writes only the WAVs + a `saved` JSON of mix/stems/dur), so `self.control`
is the only source — the same assumption the live engine uses (correct unless the
UI key was changed since recording).

Verification (byte-diff that key now flows through):
- Tenor stem (interval −2, key-dependent): **C-major vs G-major = 0.183**,
  **C-major vs C-minor = 0.005** → key/scale reach every voice's harmonizer.
- Bass stem (interval −7) is **0.0** across keys — expected, −7 diatonic steps = an
  octave, which is key-invariant. (Initially a misleading probe; re-tested on Tenor.)

Also hardened `_render_once`'s failure message (`out_path.name` → `str(out_path)`).

## 2. Tenor training-step ablation (`eval/ablation_eval.py`)
Built a standalone, **additive** eval harness for the 2k/5k/10k/15k step ablation
(documented thesis material). Imports the engine/config READ-ONLY (`SATB_VOICES`,
`diatonic_target_midi`, `f0_to_midi`) and shells out to the committed `--render` CLI
— no DSP touched, nothing in `server/`/`app/` modified. Per checkpoint × take it:
1. renders each active part solo (`--no-you`) + the full mix, C major, same voice config;
2. **metrics** → CSV/MD: F0 tracking error vs the engine's *intended* diatonic target
   (librosa.pyin, lag-aligned, in cents), RMS, spectral centroid;
3. **equal-RMS level-match** (auto target, no clip) for fair A/B;
4. **blind set**: coded `X###.wav` + a key CSV opened only after scoring.
All audio lands in gitignored `recordings/ablation/`; code-only is committed.

Refinements during the smoke test: constrained the lag search to a physical range
(was railing to unphysical negatives), and caveated that **Bass F0 is low-confidence**
(it sits ~32–65 Hz where pyin octave-errors — judge bass by ear + centroid/RMS).

### Checkpoints + A/B result (2k vs 5k vs 10k, on the scale take)
Models extracted **side-by-side** (never overwritten):
`…/260618/test/model/man/paraphernalia_data_000{05,10}000` (+ the 2k canonical dir).
- **Pitch tracking is flat across 2k→5k→10k** — tenor median ~20¢, ~89% in-tune
  everywhere. More steps don't change tuning on a clean C-major scale (saturated).
- **What shifts: level + timbre.** 5k/10k are quieter; **Bass keeps thinning and
  brightening** (RMS 0.056→0.045→0.029, centroid 281→310→**421 Hz**); 10k tenor a
  touch darker than 5k. So the verdict is by ear, not by F0 number.
- Blind key was revealed at the user's request after listening.
