## §A 包絡相關：回授路徑可量，但答不了門控的問題（`ecb6e776`＋`05fb550b`，FINDINGS **F26**）

Harry 指定的第一件。素材 `260811_bt/ear/dump_0815/`（226s，同一 callback 的 mic/out 兩軌＋逐幀 st）。腳本 `harmony/scratchpad/bank_fb_envcorr.py`。

**這不是 G34 重跑，理由可驗證。** G34 死於「迴路 `angel≈G·mic` 自相似 → 能量比恆定 → 延遲掃 0–697ms 單調無峰」，那是**即時轉換載體**的性質。bank_live 的 `y` 是音庫取樣播放（`bank_live.py:1864`），out 不是 mic 的函數 ⇒ 那條因果邊不存在 ⇒ 前提失效。

**成立的**：去 3s 趨勢後延遲掃描**峰在 +279ms、r=+0.249**（d=0 是 +0.125、掃描邊緣 +0.070），負延遲側（物理上不可能是回授）是乾淨的**負**相關 −0.24 ⇒ 因果不對稱。中位分離 **6.76×**（G34 當年 1.68×）。
> 去趨勢是必要步驟不是修飾：未去趨勢時曲線從 d=0 的 0.302 一路爬到 1393ms 的 0.372 還沒轉頭 —— 兩軌共有的數十秒尺度慢趨勢把每個延遲都墊高，峰被蓋住。

**不成立的**：判別力。而且死因不是我先判的「耦合不穩」——
- 翻出 08-10 的標定素材 `scratchpad/CALIB_*`（55s，前後掃頻夾 30s 純回授）發現**耦合平坦**：k(f) 在 80Hz–12kHz 只跨 **3.1dB**，寬頻 **−17.5dB**，正好落在本段兩個無標籤估計（−20.0／−14.8dB）之間 ⇒ 三法一致，「頻率相關耦合」的解釋是錯的，分頻帶救不了。
- 也不是 SNR：乾淨幀的預測回授相對底噪中位 **+11.7dB**，只 8.0% 低於 +6dB。
- **真正的死穴是殘差的語意**：用標定 k 算，他不出聲時 mic 仍比預測回授高 **+2.7dB 中位**（只有回授的話該貼近 0）＝麥克風裡有與回授**同量級**的非回授能量（呼吸、氣音、字間殘響、動作聲）。最佳門檻誤把回授當發聲 **35–37%**，不比已判死的鏡頭門控（閉嘴誤觸 20–35%）好，**且這 36% 是定義上的不是量測誤差**。

⇒ **G34/G35 更正開的「另錄乾淨標定素材」處方 08-10 就做過了**，而它證明問題不在標定。重開條件從「標得更準」改成**換維度**。

**方法教訓**：花在「把 k 標準一點」上的功夫全是白工——把耦合標到完美，殘差裡仍然裝著呼吸與動作聲。**先問殘差的語意，再問殘差的精度**。同 F25 的變奏：這次是照得很準、但照的不是那個東西。

## §E 「一下一下的雜音」：元兇是團員借來的真人音色（`--mem-real 0`，`8b76904e`）

**我猜錯七次**：`--frame-b64`／音庫壞音／換音瞬間／削波／顫音／滑音／線性插值。每次都要 Harry live 唱一輪。

轉折是他問：**「你就不能循環自檢，從四人版本逐步加到現在版本嗎」**。全部處理層關成裸版 → 逐項加回，**兩步鎖定**：

```
per-part 1 + 顫音              → 乾淨
per-part 4 + 顫音              → 有雜音
per-part 4 全副本完全相同      → 乾淨
per-part 4 只拿掉真人團員      → 乾淨
完整配置（六層全開）+ mem-real 0 → 乾淨（最終驗收）
```

**機制**：兩份**不同錄音**的同一個音疊加，必然有微小音高差。它在頻譜上**不是多出來的成分而是既有成分的干涉** ⇒ 任何找「異常能量」的儀器都照不到。

**五支儀器全部回報乾淨**：`dropped`（兩邊都 0）、`xrun`（只差 2 次）、高頻能量佔比、非諧波能量、自製 roughness。

**音樂上零損失**：同日 C1 已耳裁「真人音色與失諧複製分不出來」，16 人感靠失諧 25c＋起音錯開＋站位維持。引擎現在印 `0 of them a DIFFERENT singer`。

新增兩個旗標，預設皆為原行為（`--vib-sync 0` 已驗 **max-abs-diff 0.0**）：
- `--mem-real 0` 團員一律複製領唱音庫（v38 行為）← 凍結配置採用
- `--vib-sync 1` 團員與領唱共用顫音相位（診斷用，未採用）

### 血訓兩條

**① 感知類 bug 先建立最小重現條件再二分，不要從最近的改動開始猜。** 逐一猜是 O(n) 次試唱且每次可能錯；二分是 O(log n)。而試唱成本不是我的 token，是他的時間與嗓子。

**② 自製指標必須先用他已判過的樣本校準。** 我寫的 roughness 是 `num/den * energy` ＝**正比於音量**（16 個**完全相同**的副本量出 3461、單份 865——相同訊號疊加只是振幅變大，roughness 該相等）。與 **GRAVEYARD G35「CPP 只是音量代理」同一個錯，而那條血訓就寫在墓園裡。** 修成能量加權平均後 `pp4_identical` 與 `pp_1` 量出完全相同的 473.981（正確），但它也**分不出任何配置** ⇒ 指標作廢。

**③ 偶發現象要能重現兩次才算定罪。** 我單憑一次 CLI 試唱「聽起來沒有」就把 `--frame-b64` 定罪、還改了配置與 runbook —— 那次只是剛好沒唱到會觸發的音。`--frame-b64 0` 保留（它本來就多做每秒 5 次 JPEG 編碼、與 imshow 同一迴圈），但**它不是雜音的解**。
