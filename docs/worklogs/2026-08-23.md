（08-22 Harry 裁「viva 後再修，現在不動上台的檔案」）。

## 做了什麼

**1. 第一軌不再等（`toggle()`）** — 節拍器模式、還一軌都沒有時，一圈長度算得出來、而且
還沒有東西在播＝沒有既有拍點要對。所以按下去那一刻就是第 1 拍（`clk` 歸零）。
「等下一圈」只在已經有底床時才有意義。

**2. 等第 1 拍的判定從 `rec_cb` 搬到 `play_cb`（真 bug）** — 舊判法是在錄音 callback 裡
判 `(clk % L) < frames * 2`。`clk` 由播放 callback 推進，兩條是各自獨立的執行緒／時鐘，
窗口只有兩個 block 寬（<1ms 等級）。抖動一大就整圈錯過，甚至圈圈錯過＝**按了永遠不開錄**。
新判法在擁有時鐘的 `play_cb` 裡判 `(base % L) + frames >= L`＝這一塊之內會繞回起點，
一圈保證命中一次。開錄時間點最多差一個 block（5ms）。

> 註：第一次修時我猜的是「窗口太窄、抖動錯過」，寫了抖動模型去測——**測不出來**（60 次
> 全部在第一圈就命中）。所以改成不靠猜：把判定搬到唯一擁有時鐘的那條路，讓它結構上不可能錯過。

**3. 預備拍（新功能）** — `cin_beats` 預設 4，UI 速度欄旁新增「預備 N 拍」欄（0＝按了就錄）。
按錄後先數 N 拍，喇叭出短音（`_mk_click`，30ms、第 1 拍 1800Hz 其餘 1100Hz、峰值 0.30），
畫面顯示「預備 4/3/2/1」，節拍燈當倒數用。預備期間時鐘不走；數完 `clk` 歸零才是第 1 拍。
預備中再按一次＝取消，退回待命。

**4. 第 2 軌起，起點前 N 拍先敲** — `armed` 且距離起點 ≤ `min(cin_beats × 拍長, L)` 時
逐拍敲。等待不用盯畫面數。敲聲走輸出＝錄的是 BlackHole，不會被錄進去。

**5. 錄音心跳（新診斷）** — `rec_cb` 每次進來 `in_n += 1`；`pump()` 發現 2 秒沒動就講
「⚠ 錄音裝置 2 秒沒送資料進來（麥克風權限？BlackHole 沒在跑？）」，只講一次，恢復後再斷會再講。
以前錄音來源斷掉＝畫面停在「錄音中」不動，看起來像程式壞掉。

**6. 輸出裝置下拉選單（UI 底部）** — 現場可換，不用關掉重開；底床／軌數／正在錄的都不掉。
只列真的有輸出通道的裝置，BlackHole 直接排除。換法＝先 `stop()` 舊的、開新的、成功才 `close()` 舊的；
開不起來就把舊的 `start()` 回去＝不會變成沒聲音。選到名字含 `bh` 的會警告（底床會繞回 BlackHole）。

**7. 啟動器自動挑裝置** — 舊版寫死 `speaker_set`；那個聚合裝置的成員被拔掉之後
**還在清單上但 out 變成 0**，`_resolve` 找不到就 `sys.exit`＝雙擊完全開不起來（Harry 今天踩到）。
改成按 `$OUT` → `speaker_set` → `headphone_set` → `MacBook` 順序挑第一個真的有輸出通道的，
並印出跳過了誰。名字含 `bh` 的不自動選。

**8. 修 `ZeroDivisionError` 競賽（會讓整場沒聲音）** — 預備數完的那一塊裡，主執行緒若剛好
按了取消（`L` 歸零），`self.lat % self.L` ＝除以零，例外從音訊 callback 逃出去＝**輸出被關掉、
剩下的場全程無聲，畫面還一切正常**。改成在該處重讀 `L`，為 0 就直接不開錄；`toggle()` 取消時
也先把 `rec` 收掉再動 `L`。

**9. 雜項** — 新增的「預備」欄本來會吃掉空白鍵（游標停在那格按空白＝開始錄音），
現在跟速度、拍數兩格同待遇（`on_key` 守衛＋Return/Escape 交還焦點）。
