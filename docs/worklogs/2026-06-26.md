## A. Record → Arrange pipeline (B2, C1)
`studio_bridge.record_melody` captures mic → `recordings/studio_mel_*.wav` via sounddevice (no engine),
`arrange` runs `studio_api.transcribe` → score with key auto-detected. C1 switched the fixed 8s record

before arranging. Verified by live hums (key F#, 24 notes; key A, 27 notes — all 5 lines drawn).

## B. The contour editor (C2–C4)
The score draws as **5 coloured pitch-contour lines** (Melody near-black/thick + S/A/T/B), note dots,
faint semitone+time grid, DPR-crisp, redraws on resize. Editing is full-freedom:
- **Pitch drag** with a snap selector — `scale` (nearest in-key, default), `chord` (nearest current-chord
  tone), `free` (chromatic). Faint blue bands behind the grid mark the current chord's tones.
- **Onset/duration drag** — axis-locked body drag (vertical = pitch, horizontal = move onset →
  independent rhythm); right-edge drag = duration. Hover lights a voice-colour halo + a white resize
  handle; cursor switches move / ew-resize / crosshair; status shows pitch / onset / length live.
- **Note ops** — click-select + ⌫ delete; double-click **split** (leaves a gap; `drawLine` breaks on any
  time gap); ⇧-click **connect** (closes the gap, lines join but both notes keep their pitch — no merge);
  **⌘Z undo** (snapshots per drag/op). View is frozen during edits (fit only on a new score).
- **'ahh' vowel-synth preview** — formant synth, legato + playhead, per-voice solo via legend click;
  playback monophonic per voice (a note sounds to the next onset; overlap → next wins; gaps = silence).
  Alto recoloured orange→purple to separate from Tenor.

## C. Transcription overhaul (C5) — the big quality lever
Replaced the fragile `pyin → snap-to-scale → heuristic segmentation` with **Spotify Basic Pitch** (a
trained onset/offset note model) + a monophonic winner-take-all (one melodic line) + octave correction
+ a light despike. Now **faithful & chromatic (NOT key-snapped)**; no merging — repeated same-pitch
syllables stay separate notes. `min_note_s` 0.09→0.05 so fast notes/triplets survive.
**Known-hard case (all transcribers):** same-pitch multi-syllable ("steady-pitch onsets") — the
contour editor's split is the intended last-mile fix. Plus: style picker (Choral/Pad) regenerates the
draft (replace + warn-on-edits); mic dropdown prefers the USB mic over built-in.

## D. Render + export (Phase D, focus-voice commit)
- **Render → voice**: bounces the EDITED score into the user's own voice (per-voice stems + mix, via
  the existing render path) and plays it back. S/A/T/B checkboxes choose which harmony voices to include
  (`render_score` gained a `parts` filter).
- **Render → piano**: a neural-free synth from the notes — **even and never thin**, unlike the voice
  render which goes thin on big up-shifts (low male voice shifted up). Render dropdown = voice | piano.
- **Voice balance**: RMS-balance the per-voice stems + bring the lead slightly forward.
- **Export MIDI**: writes a `.mid` and reveals it in Finder.
- **SATB non-crossing**: arranger now enforces SATB ordering — the pitch SET per chord is unchanged
  (same audio) but the lines no longer cross (fixes Sop drawing below Alto on low melodies).
- **Wider voicing**: `max_shift` 8→12 so the SATB spreads instead of clustering (fixes muddy harmony).
- **Focus-voice editing**: click a legend voice to FOCUS — that line stays full, others dim, and only
  the focused voice is hit-testable, so overlapping lines become editable.

  same-pitch re-attacks). transcribe() = SwiftF0 → Basic Pitch → pyin. Removed `transcribe_crepe.py`.
  Needed `pip swift-f0` + **onnxruntime 1.16.3→1.23.2** (opset-20 model) — engine re-verified

## B. Open-license SVC / model / f0 / timbre-morph survey
4 parallel research agents (GitHub + HF, web-verified) → `docs/2026-06-26-open-svc-survey.md`.
Headlines: no open engine = CPU-realtime + zero-shot together (Beatrice's niche ~unique); male→female is
a *mechanism* problem (reference-copying / per-part trained beats source-dependent Beatrice); "4 SATB from
one singer" = speaker-embedding interpolation; flat-multisyllable is an onset problem. Permissive data:
**M4Singer (MIT, SATB labels)**, CSD/Cantoría/Dagstuhl/ESMUC/VocalSet (CC BY). See memory `open-svc-survey`.

## C. kNN-VC offline SATB experiment (the headline of this session)
Tested the survey's top hypothesis: a **reference-copying** engine should escape the male source better
than source-dependent Beatrice. Setup: **kNN-VC** (bshall, MIT — WavLM-Large + HiFiGAN via torch.hub),
reference pools from **M4Singer** soprano-1 / alto-1 (`Razer112/m4singer-combined`, HF), source = the
user's male singing; compared against Beatrice's female model on the same clip.

Results (all by ear):
- **kNN-VC → alto = GOOD, and alone BETTER than Beatrice's neutral female.** ✅ Hypothesis confirmed for
  the normal vocal range.
- **kNN-VC → soprano = BAD.** kNN-VC does not pitch-shift; soprano sits ~an octave above the male source.
  - Tried **librosa pitch-shift +12** → "chipmunk" (formants shifted too) → WavLM out-of-distribution →
    muddy/"underwater" output.
  - Tried **WORLD/pyworld formant-PRESERVING +octave** → source sounded **natural** (user confirmed) →
    but kNN soprano output **still bad**. So it's not the shift quality: **kNN-VC itself can't handle
    soprano** (WavLM trained on normal speech → high-register singing is OOD; alto worked because it's
    in-range).

**Conclusion (offline SATB via kNN-VC):** **A/T/B = kNN-VC (MIT), beats Beatrice; soprano = dead end for
kNN** — needs a pitch-native trained SVC (RVC/so-vits on M4Singer soprano) or stays on piano/Beatrice.
Cost: kNN-VC is offline-only (~19 min / 5 s on CPU, no MPS used) — viable for a future **offline render**
option (cache reference features + MPS + resident model), never live. Nothing wired into studio; live
engine untouched. See memory `knn-vc-satb-finding`. Scratch: `knnvc_test.py`, `m4ref/`.
