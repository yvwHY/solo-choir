## B. PLA 重切（11:2x，PrusaSlicer 2.9.6 CLI，同昨夜流程）

- 耗材段換法：不手抄數字——從已安裝 vendor bundle（`~/Library/Application Support/PrusaSlicer/vendor/PrusaResearch.ini`）解析 **Generic PLA @MINIIS** 完整繼承鏈，與 PETG 版逐鍵 diff 後精準替換 `petg_p2.ini`/`petg_bponly.ini` → `pla_p2.ini`/`pla_bponly.ini`（每條替換驗證恰好命中一次）。關鍵差異：溫度 240/245/85→**230/220/60**、風扇 30–55%→**100%**、volumetric 9→14、M572 壓力提前 0.36→0.27、PETG 專屬 retract 覆寫（speed 45/deretract 25/before_travel 1）歸還 **nil**（回印表機預設）。
- 三盤重切（一盤一次 CLI、不用 `-m`，照 README §E 雷區）：P1 盒身 3h19m/46.1g、P2 蓋 37m/12.0g、P3 bce×2 45m/8.5g——全 <5h。
- 驗證：三檔頭部 filament/溫度/支撐鍵全對；擺位 vs PETG 版——P1/P2 `objects_info` 逐字相同，P3 僅 hull 單頂點差 0.07mm（切片器簡化抖動，實質相同）。
- 檔案紀律:PETG 三檔移 `gcode/petg_hold/` 留存（日後有 PETG 機再用），`gcode/` 頂層只剩 PLA 版＝帶去 lab 的就是它們；README 加 §F 記錄全程。

## C. 材質換 PLA 的下游影響（記錄，不擋印）

WO-5 J-ribbon 鉤當初避開 C-clip 是因「恆力握持 = PETG 潛變風險」；PLA 潛變更明顯但 J-hook 本來就是「零應力掛置」設計（重力走剛性冠、snap 只防跳），方向不變。喉口 2.7 打樣本來就要 ±0.1 迭代，PLA 彈性略低 → 若太緊優先當尺寸問題調 CAD，不先怪材質。

## F. 晚間：OLED/Pico W Stage-5 點亮 — 成功（學校載板，非裸板）

- **板子換了**：不用裸 Pico W 手接線，改用學校的 **Goldsmiths Physical Computing 25-26 載板（Robert Hall）**——Pico W 插座 + 板載 0.96" SSD1306 + touch/gyro/light/SD。省掉接線步驟，但腳位假設全部重查。
- 流程：BOOTSEL 刷 MicroPython v1.28.0 UF2（一次過）→ 全組合 I2C 掃描定位 OLED → 改 `main.py` → `mpremote cp` → 重開機自主執行。
- **發現一（腳位）**：載板 OLED 在 **GP4=SDA / GP5=SCL**（demo 原假設裸板 GP0/GP1）。同一條 bus 還有 accel 0x1C ＋ **LSM6DSO gyro 0x6A**（WHO_AM_I=0x6C 實讀確認）——之後要用都是現成的。
- **發現二（重要坑）**：**RP2040 硬體 I2C 在這載板上不能用**——位址探測 ACK、但任何資料位元組一律 `EIO`，100k/50k/10kHz 全滅，三顆裝置同病（一度誤判為寄生供電/On/Off 電源閘，實測開關無關）。**換 `machine.SoftI2C`（bit-bang）立刻全通**，400 kHz 下實測 **~29 fps**（純畫圖迴圈；main.py 含 20ms sleep 後每幀 ~53ms）。
- **驗證（Harry 目視）**：嘴型隨假 level 開合、眨眼每 ~10–12 s（=180 幀週期 × 實際幀時 ~53ms ≈ 9.5s，與程式相符；註解原寫 3–4s 是理想幀率估的）、板載 LED 快閃、拔 mpremote 後自主執行。
- 檔案：`SoloChoirCode/260716_pico_oled/main.py` 已更新（SoftI2C + GP4/GP5 + 坑註解）；`ssd1306.py`＋`main.py` 都在板上，開機自動跑。
- **Stage-5 意義**：韌體→驅動→動畫 pipeline 全驗證。下一步 telemetry 嘴型版 = 換資料來源（Mac 端發送口 + WiFi 收）＋沿用這套畫面，另開 session；最終螢幕尺寸拿著原型再決定（roadmap 07-14 凍結不變）。
