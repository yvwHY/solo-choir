## A. Device-switch timbre collapse — REAL root cause (the prior diagnosis was wrong)
The bug: on a fresh launch the JVS Sop sings as genuine female; the moment you switch an audio
**device**, the timbre collapses to neutral ("my own voice pitched up") and stays collapsed until a
full app restart. Session 1 blamed **input overflow corrupting Beatrice's input** and tried to fix
the *audio path* (split streams, dedicated raw-mic input) — all failed. The disproof was already in
hand: a **clean dedicated-mic input stream still collapsed** → it was never input corruption.

**Real cause — the `model` field gets dropped on restart:**
1. The UI's `controlState()` (ui v10) sends `voices` **WITHOUT `model`** — model is bridge-owned
   ("model is set HERE"); the UI only carries on/interval/octave/formant/speaker. `send()` fires on
   almost any interaction (incl. a global `pointerup`), so one click is enough.
2. Bridge `set_control` did `self.control.update(ctrl)` → this **replaced** `self.control["voices"]`
   with the model-less UI array; `"jvs"` was gone.
3. A device (or model) switch → `_restart_engine` → `_start_engine` serializes `self.control["voices"]`
   into `--voices` → now model-less.
4. Engine `_build_voice(d.get("model", "tenor"), …)` → **defaults to "tenor"** → every part rebuilds
   on the **male tenor model** instead of jvs. Male source + male model → output ≈ original male
   timbre. **Centroid 2290→1088, f0 unchanged** — exactly the measured symptom. Persists until app
   restart because only `Bridge.__init__` resets control to `JVS_SATB_VOICES`.

Proven **deterministically, no audio**: ran the real `set_control` + restart serialization →
voices resolved `'tenor','tenor','tenor'` (was `'jvs'`). This is why the prior audio-path attempts
(suspect a/b — clock/duplex) all failed; suspect **(c) — `_send_control`/restart changes the
conversion** — was the right lead. ([[beatrice-source-dependent-conversion]] is the *mechanism* of
the collapse: male src + male model = male out.)

## B. The fix (`16615f39`, `app/bridge.py` `set_control`)
Before `self.control.update(ctrl)`, **re-stamp `model` per part** from the existing
`self.control["voices"]` when the incoming voice omits it. Model survives → restart rebuilds on jvs.

(harmless — the engine can't change model live). **Verified by ear:** click around → switch output
to MacBook speaker → **Sop holds female** across repeated switches. `set_model` shares the same
restart path → fixed too. Memory `unsolved-device-switch-timbre-collapse` updated to **SOLVED**.

## G. Parent-death watchdog — the orphan-engine fix (`b90cd40a`)
The §D gotcha got a real fix. `shell.py` runs `bridge._start` (engine + telemetry) on a **worker
thread**; the main thread sits in Cocoa's event loop, so Python **signal handlers are unreliable**
there — a bridge-side `signal.signal` fix would be fragile. Did it **engine-side** instead: a daemon
thread polls `os.getppid()` and `os._exit(0)`s when it changes (macOS reparents to launchd on parent
death). Covers every orphan path (crash, signal-kill, kill -9) without touching signals/stdin. Armed
**only for the live stream** (after the `--render`/`--list-devices` early returns) → `--render`
byte-identical by construction; manual-CLI unaffected. Verified: `kill -9` the app process → the
orphaned engine self-reaped in <2s (was: orphan forever).
