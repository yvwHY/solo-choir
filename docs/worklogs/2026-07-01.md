## Mask frame — a 3-step Blender reference series (`hardware/mask_frame/`)
The wearable mask is hand-built from wire + fibre. Rather than model a printed part, these scripts
build an **on-screen reference** in Blender (driven over the MCP socket) to bend the real frame
against. Each script is re-runnable and byte-stable; nothing is printed. Run them in order.

- **STEP 1 — `01_import_head.py`:** bring the mannequin bust (`head.glb`) in as a scaled, upright,
  wireframe reference. Four socket-driving bugs fixed along the way (all noted in the commit): the
  glb is one Sketchfab mesh under a 100×-scaled ~15 m-offset empty (join-all blew it to ~30 m — now
  bake `matrix_world` into the verts, reset to identity, delete empties); `transform_apply` /
  `parent_clear` silently no-op over the socket without a 3D-view context (use `head.data.transform`
  instead); `select_all+delete` skips a `hide_select` object (a prior Head survived — clear via
  `bpy.data.objects.remove`); bust sat ~0.6 m below origin (drop min-Z to 0). Result: face width
  145 mm, faceless bust standing on the grid + a FRONT_marker.
- **STEP 2 — `02_place_component_markers.py`:** four labelled, movable, colour-coded markers snapped
  to the bust surface with an outward offset, positioned from neck/head geometry (not hard-coded
  heights): **DAEX cup** (off the mouth), **Bone L/R** (cheeks, in front of the ears), **Throat mic**
  (larynx). Live in a re-run-safe `Components` collection; drag to exact spots.
- **STEP 3 — `03_frame_reference_lines.py`:** the RIGID **front-of-face island** — the part that
  holds the DAEX cup off the mouth — drawn as movable tube curves standing a fixed **STANDOFF = 18 mm**
  in front of the face: `Frame_rim` (closed oval around the face perimeter), `Frame_centre`
  (forehead→chin midline strut), `Frame_mouthcross` (cheek→cheek at mouth height). Rim + the two
  struts cross at the mouth, where the cup rides. Heights derived from the neck/head geometry; each
  point snapped to the frontmost face vertex minus STANDOFF. This island is deliberately **mechanically
  SEPARATE** from the bone / throat mounts (the decoupling in HARDWARE_ROADMAP §"one shell, two isolated
  islands" — the bone transducers ride an elastic band, not this frame). In a `Frame` collection,
  reshape by hand.

## Infra — Fusion 360 MCP bridge now loads in Claude Code
The bridge add-in and MCP server were installed + hardened on this same date, but the
`mcp__fusion360__*` tools never actually appeared in Claude Code. Root cause: the server had been
registered under `~/.claude/settings.json` → `mcpServers`, **which Claude Code does not read for MCP
servers** — so no amount of restarting loaded it. Fix: register at user scope with
`claude mcp add fusion360 --scope user -- <venv-python> <server.py>` (writes to `~/.claude.json`);
`claude mcp list` now shows `fusion360 ✔ Connected`, tools load after a session restart. The server
reads its secret from `~/.fusion-mcp-secret` directly (no env needed). Reference memory
`fusion360-mcp-claude-code` corrected. Fusion is now drivable from Claude Code (write `adsk.*`
Python → run → screenshot → iterate), same loop as the Blender bridge — the intended next tool for
turning the hand-built frame reference into actual CAD. (Security unchanged: `fusion_execute` is
unsandboxed arbitrary code exec, token-guarded; stop the add-in when done, don't process untrusted
web content while it's live.)
