## A. Strategic reframe (the meeting → the research vision)
Yee-King's strongest, repeated advice was methodological: don't ship one finished thing — build a
**comparison/baseline** and **do a bit of science** (he leans the project toward a research
framing, which suits a PhD / MIT Media Lab application). The standing engineering decisions held up:
**don't switch the live engine** (RAVE/DDSP/ACE-Step have no pitch control, need a GPU + weeks of
training; we're CPU/Mac), and **don't chase self-trained quality** (write it up as a finding).

The design conversation then unified the two halves of the thesis under the proposal's own title —
*A Wearable Instrument for Learning and Extending the Singing Body*:
- **Learn in-body** — bone conduction (open ear) delivers an independent target while you still hear
  your own voice; the testable claim is *open-ear bone conduction beats closed headphones for
  learning* (occlusion effect). This is now the **core** of Track B (it returned from "PhD-only").
- **Perform from-body** — the synthetic choir emanates from / is felt in the body; **simultaneity**
  (one body = a whole chord at once) is the literal "extending the body". The DAEX mouth-rig was
  **reframed as an embodied/spatial source, NOT a formant filter** (that needs a talkbox tube; and
  software already owns timbre — retracted after acoustics research).

Captured in `SOLO_CHOIR_RESEARCH_VISION.md` (zh/en) and a realigned `HARDWARE_ROADMAP.md`.

## B. Track A — the harmony ear-trainer (built in 4 phases)
Goal: turn the existing Record→Play into a tool that teaches you to sing a harmony part. The key
enabler was already true in the engine: **the mic is still analysed during playback** (the reference
voice always runs), so live pitch is available while a target plays — no audio-thread change needed.

- **Phase 1 — per-part solo playback.** New `play_file` control + an **off-thread stem loader**
  (mirrors `_take_writer`) and an additive playback branch that prefers the loaded stem; the existing
  Melody/Choir/Both path is untouched. Added **practice mode** (live mic keeps driving the readout
  while a target stem plays) and an **exactly-synced playhead** — the engine now reports real loop
  position (`play_t`/`play_len`) in telemetry, and `take.dur` is set to the engine's true take length
  so notes + playhead share one timeline.
- **Phase 2 — feedback, evolved by ear.** Started as a target-relative **cents needle**; by-ear
  review showed a real-time needle is twitchy and makes you *chase the centre* instead of *sing the
  right note*. Final design: **note-match** — `Sung` vs `Target` note names, octave-folded, with 3
  calm states (`✓` / `♯ high` / `♭ low`, Sung turns green on match). Target = the soloed part's
  diatonic note off the recorded melody (reuses the UI's `diatonicShift`, no bridge/wav_to_notes).
  The **live chromatic tuner was removed entirely** (twitchy; no fixed reference for solo a cappella).
- **Phase 3 — multi-select part tabs.** First tried a Match/Hold toggle; it read as unintuitive, so
  per the user it became **independent on/off tabs in the transport row**: after a render the row
  swaps to **`You · Bass · Tenor · Alto · Sop · All`**. Playback = the **SUM of the on parts**, summed
  in the bridge (`play_mix`: read on stems → sum → fresh temp file → `play_file`; **no engine
  change**, no extra inference). This subsumes hold-against (turn your own part off, leave the others
  on) and ensemble practice. `All` toggles everything on/off. Target feedback shows only when exactly
  one *harmony* part is on (one = match; multiple = hold by ear; You-alone = your own melody).
- **Phase 4 — logging for the study.** Each continuous single-part attempt (≥1s sung) is logged on
  leaving the part: the UI accumulates time-weighted stats from the per-frame match, and
  `bridge.log_practice` appends to `recordings/practice_log.csv` (gitignored). Columns:
  `time, part, key, scale, voiced_s, match_pct, mean_abs_cents, on_target_s` — the raw "did you learn
  to hold the part" metrics for the evaluation. Verified with real attempts (sane rows).
