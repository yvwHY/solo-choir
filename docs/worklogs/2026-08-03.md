## §B 第一刀：兩張嘴共用「只看 x」的那一層（commit `8d1bea36`）

拆帳同時看到一件純浪費：`input_agc` 與 `voicing_conf` **各自呼叫一次
harvest**，兩張嘴又各跑一遍＝**同一段音訊被 harvest 四次**。而 `input_agc`、
`voicing_mask` 本身也只看 `x`（跟聲部無關），照樣算了兩遍。原本的 `shared`
只快取 units/vol。

改法：`harvest_f0()` 抽成單一入口，三個函式加 `f0m=` 選填快取參數；
`PhraseRenderer` 的 shared 從 `{units, vol}` 擴到
`{f0m, agc, vm, units, vol}`，並加「換句沒清快取」的守門（存 `len(x)`）。

驗證（Regime：MPS 渲染不可重現 → 比 self-noise 地板，08-01 §D 的規矩）：

- 模型輸入**逐 byte 相同**：input_agc 增益曲線 `max|diff| 0.0e+00`、
  voicing_mask `0.0e+00`（快取 vs 重算）。快取不是近似，是同一個函式對同一份
  輸入。
- 輸出 6 句 `max|diff|` 0.076–0.191／corr 0.9955–0.9973，同碼兩跑的 self-noise
  地板 0.067–0.227／corr 0.9952–0.9985 ＝**落在噪音帶內**，逐句不劣於自己跟
  自己比。
- 速度：16.7s 素材 7.92s → 3.88s（RTF 0.47 → 0.23）、**2.04×**。

## §C 第二刀：管線化——他還在唱的時候就先算（commit `3f24b098`）

原則只有一條：**只先算「分段算＝整段算逐 byte 相同」的東西。**

| 可以先算 | 為什麼 |
|---|---|
| 腦（EarV3） | 本來就是逐 tick 串流，樣本與順序一樣＝結果一樣 |
| voicing 逐幀特徵 | 每幀只看 `[k·HOP−1024, k·HOP+1024)`（新 `dm.voicing_frames`） |

| 不可以先算 | 為什麼 |
|---|---|
| harvest | 路徑搜尋跨全段 |
| hubert encode | transformer 全注意力，切了 units 就不同 |
| `_local_ref` | ±3s 窗 |
| model forward | 切了就有接縫與相位跳 |

這條線是**刻意畫的**：把 encode 或 forward 也切掉還能再省 ~0.6s，但那會變成
另一張嘴——而那張嘴是 08-02 Harry 耳測裁「還行」的那張。寧可多等 0.6s。附帶
好處：forward 仍然整句一次跑完，所以沒有接縫、不需要交叉淡化、沒有相位不連續。

落地：

- **`PhraseGate.committed()`**——交出「保證會留在這一句裡」的樣本。兩個保證：
  ① 尾端裁切最多 `gap_w+1` 個窗（`force_end` 裁得更少），② 長度過 `min_w` 後
  `push` 與 `force_end` 兩條路都必定收句（不會走「太短當誤按、整段作廢」）。
  少了②，誤按按鈕時腦會吃到一段不算數的音訊。
- **`Prefetch`**（背景執行緒）——吃 committed、餵腦、算 voicing 幀；句尾
  `finish()` 補完剩下的並回傳 `(notes, shared)`。前綴對不上就整句重算，例外
  一律印警告後退回重算（不擋路原則）。
- `make_response(pre=)`、`--no-pipeline` 退路、**`resp2_probe.py`**（新儀器）。

## §G 殘響與混音平衡定案（Harry 耳測四輪，commits `3aa2d683`＋`842537c0`）

Harry：「可以加上好聽的 reverb 嗎」。回應本來就是「一群人在某個空間裡唱」，
而它到今天為止完全乾。

**為什麼是卷積不是演算法殘響**：Schroeder/FDN 要調一組互質梳狀延遲，調不好
的失敗模式就是**金屬感**——正是 07-30 §F–§I 花三天殺掉的東西。指數衰減的高斯
噪音是最大密度的擴散場，天生沒有梳狀峰，**沒有可以調壞的地方**。`reverb.py`
（零採購零新依賴，scipy 已在 venv）：predelay 20ms → 早期反射（10 個離散 tap、
間隔刻意不規則，等間隔＝flutter echo）→ 晚期尾巴（前 30ms 淡入，回聲密度是
長出來的）。**讓它像房間而不像效果器的是分頻帶衰減**（低/中/高 T60 ×1.2／
×1.0／×0.4；單一 T60 的白噪尾巴會「嘶」）。

### 四輪的路徑

| 輪 | 問題 | 判決 |
|---|---|---|
| 1 | 四格盲聽：乾／廳只天使／教堂只天使／廳全部 | **「有空間感，自己也進去」** |
| 2 | 混音平衡（見下） | **dry-gain 1.1** |
| 3 | T60 階梯 1.8/2.2/2.5/2.8（送出量固定） | **「好像確實差不多」** |
| 4 | 尾巴截斷 不截／−45 dB／−35 dB | **「差不多」→ −35 dB** |

所有比較都**整體響度對齊＋共用同一個防削峰係數**——殘響本來就會讓東西變大聲，
不對齊的話盲聽會退化成「比誰大聲」。（第一版忘了這件事：先對齊 RMS、再各自
防削峰，把對齊又抵銷掉，四格差 1.7 dB。）

## §F 穿戴 mesh coupon：兩片都太硬 → 換家族＋軟化（對話 session，未 commit）

### v2 的死因：先排除切片，再剩兩個候選

gcode 分析是決定性的一步，而且結果跟直覺相反：

```
613 ;TYPE:External perimeter
612 ;TYPE:Perimeter
  7 ;TYPE:Solid infill        ← 只有板
  0   Gap fill
```

**一行 Gap fill 都沒有**——slicer 確實把每條 0.6mm 縫當成孔洞繞了輪廓。所以
「拉不開」不是切片把縫填死造成的，**改切片設定沒有用**。剩兩個候選：

- (a) **物理**黏死：0.6 名義間隙、兩側各一條 0.45 external perimeter，擠出膨脹
  加 PLA 塌陷後實際可能只剩 0.1–0.2mm。gcode 看不出來。
- (b) **機構鎖死**：rotating squares 是**單自由度機構**（全片只有一個變形參數
  θ，所有方塊必須協同反向旋轉），而中央 ⌀55 是連續實心板，把它底下那批方塊焊
  成剛體 ⇒ θ 在那裡被強制為 0 ⇒ **整片鎖死**。實際材料有柔性所以不是絕對鎖死，
  而是變形只能靠材料應變、不能靠機構旋轉，剛度上升一個數量級——**症狀是「硬」
  不是「斷」，這正是 (b) 的特徵**。

**鑑別測試：從角落剪 40×40 純網區單獨拉。拉得開＝(b)，拉不開＝(a)。**
⚠ **未執行 → 根因未定 → 尚未登記 GRAVEYARD**（條目要寫 root cause，現在寫不準）。

### v3 太硬的根因：我只動了三個旋鈕裡的一個

桿件的面內彎曲剛度 ∝ **t·w³/l³**（t 片厚、w 桿寬、l 桿長）。v3 只調 w，而
w 的下限是 **0.8＝2 走線**（再降就掉回 v2 的窄縫坑），所以我以為旋鈕用完了。

- **l 同樣是三次方項，而且沒有地板**——當初選 6.94mm 只是為了「格子看起來密」。
- **t 更糟：從 v1/v2 整包沿用 0.8，從沒重新問過**。v2 是切縫片需要面外剛度，
  v3 是桿件網根本不需要。

**血訓（一般形式）：換家族的時候我重新想了「機構」，卻把上一版的尺寸參數當常數
搬過來。沿用的參數要跟著新家族重問一次「這個數字為什麼是這個數字」。**
跟 08-01「參數繼承要驗證」是同一課，這次是硬體版。

另外「越往內越硬」有**兩個**疊加原因，Harry 猜到第一個：桿寬漸變（設計意圖），
以及**中央板本身就是剛體**（不參與變形，還吃掉 150mm 裡的 55mm）。

### 三個新版本＋兩個對照組

- **v5**＝v3 軟化：格子等比 1.5×（W 12→18／HV 9→13.5／S −3.5→−5.25）＋片厚
  0.8→0.6。**桿寬漸變刻意不動**——內外差異是設計意圖，這次修的是整體剛度。
  預估整片剛度 **×0.23**（桿長 ×0.296・片厚 ×0.75・並聯列 12.5→8.3 使 ×0.67・
  串聯排 25→16 使 ×1.56）＝位移約 4.3×。**估算，未實測。**
- **v4**＝交錯直縫 kirigami：保住 v2「印時近實面→張力下浮現蕾絲」的語言，但縫
  的拓撲換掉，縫數 650→~160。縫寬因此能放寬到 **0.8＝2 走線必定留空**，而
  **開孔率反而 11%→7.4%＝比 v2 更像實面**。漸變用的是跟 v5 同一招：**只動不移
  動節點的參數**（縫週期固定 20.0、縫長隨半徑變 ⇒ 縫中心不動）。縫端改 round
  cap＝洩壓孔（v2 用 flat cap，縫端是直角，而那正是鉸鏈根部的應力集中點）。
- **v3/v5 無板對照組**（`*_noplate`）：**只移除板，桿寬漸變刻意保留**，單一變數
  才可歸因。讀法：無板明顯好拉 ⇒ 板是主因，**最終件的板必須跟網解耦**（浮動接
  合／過渡帶），不能像現在直接 union 成一體；差不多 ⇒ 板無罪，續走 v5 的旋鈕。
