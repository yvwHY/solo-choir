# 下半場續（腦 → solo_min session）— §R 滑音修正：外控 steps → 絕對音釘選（commit `d9453f2a`）

## 根因兩層（都在外控 steps 路徑的結構裡）
1. **追不上的目標**：F2 防刮 glide＝debounce 80ms＋4 半音/秒逼近；但 pin 事件平均 ~86ms 就改寫一次 steps → `_glide_target` 到達前又被搬走＝永久 portamento。量測：天使滑音時間 **35%** vs Harry 原唱 16%、持音段 8.1s vs 27.4s（YIN、150ms 中值後 |slope|>4st/s；工具留 scratchpad `measure_glide.py`）。
2. **兩套音高參考打架**：pin 用瞬時 rounded-MIDI，引擎用 hysteresis held-note（死區 0.5＋1.0＝1.5 半音）——**C 大調 1 半音級進（E→F、B→C）永遠不觸發 re-lock**，steps 瞄準基準過時 → 天使整段唱錯 ±1 半音。相關性診斷：天使音高誤差 vs Harry 對格偏差 **corr=0.03**（不是人聲透傳，Harry 只偏 28c）。

## 修正（server/ 依然零改動）
- tick 直接設 harmonizer 既有的 **`abs_target_midi`**（MIDI Mode A 機制，solo_min 一直沒接線）：引擎每 frame 用自己的 held-note 重算補償 shift——單一參考、沒東西可追；`deg()`/steps/pin 整套刪除（set_control 只剩 on1）。
- **`--glide 0`**（既有旗標）：補償瞬時跳。abs 模式下 held_m 抖動被重算的 shift 精確抵消（絕對目標不動）→ hysteresis 死區失去存在理由 → **`note_hysteresis 0.05`＋`note_smooth_frames 4`** 讓輸入音估計保持新鮮（per-voice 屬性 in-process 設，非 server 改動）。
