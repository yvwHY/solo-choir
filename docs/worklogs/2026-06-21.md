## A. Multi-voice noise → Route A (pump)
Diagnosis: the live multi-pass 滋滋波波 is **deadline-coupling** — inference ran *inside* the
sounddevice callback, so 3–4 passes near the 10ms deadline glitched. **Route A** moves inference to
a WORKER thread feeding **preallocated, lock-free SPSC ring buffers**; the audio callback only moves
samples (zero alloc, zero locks — the first naive pump still allocated/locked in the callback and
crackled; the lock-free rewrite fixed it). **GIL spike**: Beatrice `convert()` *releases* the GIL
(p99 wake-delay ~3.6ms ≪ 10ms) → threads are viable, no multiprocessing needed. `--render` stays
**byte-identical 0.0** (live-only path). `--cushion-ms` trades prebuffer vs latency.

**Latency reality:** the Aggregate Device + Beatrice's 10ms hop floor ≈ **47ms**; Vocoflex's 35ms
needs a lower-latency device, not just code. Tier-1 (just `--latency low`) gives **clean single/2
voices @ ~47ms**; **3+ passes in-callback crackle**. The app `--pump` path was clean in CLI but the
GUI (three.js + telemetry) **steals CPU in bursts** → underruns; a lite no-WebGL UI helped but did
not fully solve it. Live 3–4 clean is still the rough edge.

## D. Harmonizer crackle ROOT CAUSE (found + fixed) — `cacb30b4`
A sharp user observation cracked it: even at a good input pitch, the harmonized note crackled, while
a **fixed** shift at the same output pitch was clean → the crackle is the **dynamic harmonizer**, not
the model range. Mechanism: the harmonizer snaps the input to an **integer-semitone** shift; vibrato
made the snapped held note **flip-flop** across a scale boundary → the applied shift **stepped** →
every `set_pitch_shift_semitone` change **glitches the neural synth** → the sustained-note 吱吱.
**Fix:** a **cross-frame median** (~12 frames/120ms) holds a sustained note's snapped pitch steady
under vibrato (the vibrato rides the raw f0 smoothly through the shift). A **shift-glide** was also
tried and **reverted** — calling `set_pitch_shift_semitone` every frame during the ramp made a
*worse, rhythmic* glitch (fixed-tempo, independent of singing — the tell). Also found earlier: the
single-voice path's control `intervals` override silently forced the launch `--interval` (so a
descriptor's interval was ignored at 1 voice — pass `--interval` to test a single voice).

## E. Live harmony arrangement + the TWO feedback causes
Prototyped **You(melody) + Tenor(3rd below) + Alto(3rd above)**, and a **tenor↔alto pitch
crossfade** voice (`xfade_test.py`: both models run, equal-power crossfade by target pitch — low =
tenor, high = alto blooms female; user dropped the dual-model for cost). Then full **SATB** (Bass =
tenor model octave-down, Sop = alto model octave-up).

**Feedback — two separate causes, both nailed:**
1. **You passthrough** = the raw mic in the output → fastest acoustic loop; every "You out loud"
   config howled, every `--no-you` was clean.
2. **The Aggregate Device's output includes the built-in speaker** → sound leaks speaker→mic; the
   loop gain crosses 1 as voices (output level) increase, so 2 voices were fine but 4 howled **even
   on `--no-you` + headphones**. Fix = route output to **pure headphones** (not the
   aggregate-with-speaker), or remove the speaker from the aggregate in Audio MIDI Setup.

## B. Live reverb — the saga, and what actually broke (`c8a5a28e`)
Wanted "church space" **live**. Offline convolution (route B) is trivial but live convolution is hard;
chose **algorithmic (route A)**. Three real bugs, found in order, each masking the next:
1. **Orphan engines**: `pkill -f app/shell.py` killed only the shell, not its spawned engine subprocess →
   3–4 engines piled up all fighting the **same aggregate device** → mush/feedback that **confounded
   every reverb test** ("完全不像/沒距離感"). Fix: always `pkill -f beatrice_solo_choir_live.py` too.
2. **No distance**: the first mix was `dry(full) + wet` → voice stays in your face. Fix = **recede the dry
   as amount rises** (low direct-to-reverberant ratio) + **pre-delay**.
3. **NaN → silence**: a single inf/nan in the neural harmony **permanently poisoned the IIR state** (lfilter
   zi) → all-nan → silent. AND the **lfilter** Freeverb was **too expensive: RTF 1.35 > 1.0** → pump starved →
   silence. Both fatal. **Rewrote as cheap, stable circular delay-lines** (vectorised sub-blocks ≤ shortest
   delay; buffers clamped+`nan_to_num` every block). Offline-verified: no NaN under inf injection, **RTF
   contribution ~0.01** (vs ~1.0), real decaying tail. Kept; UI "Space · 殿堂" slider sends `reverb` 0..1;
   amount==0 → bypass → byte-identical. **No latency added to the dry path** (only the wet tail trails).
   (Final by-ear "is it church enough" tuning still open — `_wetgain`/`room`/`_dryduck`/pre-delay are the knobs.)
