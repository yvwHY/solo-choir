## §A `respond2.py --live`：忙碌窗硬靜音（commit `c7bdeab5`）

麥克風進、喇叭出的狀態機：**聽 → 斷句 → 硬靜音 → 腦＋離線正典渲染 →
播回應 → 殘響尾巴過了才復聽**。

**硬靜音涵蓋整個忙碌窗（含渲染期），不只播放期。** 這是刻意的：渲染中他若
開口，那句會被收進下一次判定，而回應播出時他正在唱＝踩 07-16 G「回應只在
他不唱時播」的紅線。08-01 的前提本來就是「唱/播不同時活著」——結構上不
同時，就不需要偵測迴授、不需要判斷喇叭聲是不是他、回應也滲不進下一句。
代價：這段窗內麥克風聽不見他，所以實體鍵成為他唯一的發話管道（§B）。

實作要點：
- `PhraseGate`＝`find_phrases` 的串流版。判準逐項鏡像，**連 find_phrases 收
  尾少算一個有聲窗的 -1 都刻意複製**——兩模式必須切出同一句界，否則 file
  模式的耳測結論對 live 不成立。要改就兩邊一起改。
- `make_response()` 抽出＝file/live 共用同一份回應配方（dry 0.5＋兩天使
  0.6、polish、shared hubert encode），不會各自漂移。
- session dump：靜音期把他的輸入寫 0、播放期寫播出去的，同軌落檔＝**硬靜音
  的證據**，也讓整條 call-response 可以事後耳測。
- SIGINT 還原（07-31 §H 血訓：背景 shell 起的行程 Ctrl-C 全空包）。

## §B 開場自動校準＋實體鍵接上（commit `7918ca9d`）

### 斷句門檻現量，不繼承

`RMS_GATE = 0.02` 是對著**喉麥素材的換氣**（~0.01）調出來的。換空氣麥克
風、換場地、換增益，這個值沒有任何理由成立——08-01 已經因為「參數繼承
沒驗證」翻車兩次（斷出 34.6s 的「一句」）。所以 live 開場現量：

- ① 安靜 3s → 底噪 p95；② 唱 5s → 位準 p75；gate＝兩者在 log 域的中點。
- 順帶把 **分離度 dB** 印出來＝08-01「待錄那格」（K669B 站姿實唱、驗輸入
  SNR）的儀器現在先備好了：錄一次同時回答「SNR 撐不撐得住」與「gate 設多
  少」。<12 dB 直接警告別硬跑。
- **刻意往高的一邊錯**：安靜段量得到房間底噪、量不到換氣，而 gate 偏高＝
  句子被切碎（回應照樣成立、只是句短），偏低＝斷不出句、整首變一句（08-01
  實測的 34.6s）。後者才致命。另印唱段 p10（換氣／空隙位準）當對照，gate
  低於它就警告。
- 底噪地板 1e-4：數位全零輸入（介面靜音／線沒插）會讓 gate 算成 0＝什麼都
  算有聲、永遠斷不了句。
- `--gate` 有填就跳過校準；file 模式維持 0.02（沒有現場可量）。

### 實體鍵（`tap_listen` UDP :8766）接三個時機

靜音期麥克風聽不見他，按鈕是他唯一的發話管道：

| 時機 | 行為 |
|---|---|
| 聽的時候按 | 不等 gap，立刻收句（`PhraseGate.force_end`） |
| 渲染中按 | 這次回應作廢，直接回去聽 |
| 播放中按 | 30ms 淡出中止（免爆音），尾巴只留 50ms |
| 手上不足一句 | 忽略（按鈕不擋路：按錯不會讓系統卡死） |

收不到鍵／埠被佔＝退化成純能量判定。狀態列印 heartbeat（上台前確認連線）。
probe 用 UDP 直接打進 TapListener（不需 Pico），**四條路徑都實際觸發到**。
