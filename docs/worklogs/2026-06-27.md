## Exciter R-mute was dead code — fixed
The exciter on/off control (`aab81979`) never did anything. Root cause: both `sd.Stream` calls in
`server/beatrice_solo_choir_live.py` opened output as **mono** (`channels=1`), so `if outdata.shape[1] > 1`
— the R-mute gate — was unreachable. The single channel was duplicated to both physical outs by the
USB sound card, so "exciter off" kept sounding. Diagnosed by instrumenting the engine/bridge with
temporary stderr debug (had to bypass `conda run`, which buffers child stderr until exit, and launch
with the env python directly + `PYTHONUNBUFFERED=1` to see it live); the debug line read
`outdata.shape=(480, 1)` — the smoking gun.

Fix: open output as 2ch (`channels=(1, 2)`, input stays mono mic) so L=bone / R=exciter physically
exist; also gate the pump path's `_thin_cb` R-copy by `exciter` (it unconditionally duplicated to R —
a second dead path). Verified by ear on the `throat` aggregate: exciter off silences R, bone (L)
keeps playing. Normal stereo speakers unaffected (R=L when exciter on). Offline `--render` unchanged
(no stream opened).

## Test A — feedback / Beatrice self-stacking threshold — **PASSED (by ear, pilot)**
Setup: throat-mic worn, bone-conduction transducer attached, exciter handheld. Real singing (not just
a sustained `/a/`), exciter brought very close to the mic.

- **Classic ring (structural/acoustic feedback): not observed** across all realistic placements,
  including exciter held very close. The *only* squeal was when the exciter was **deliberately placed
  directly on the throat-mic** — an extreme stress case that the planned **mask architecture will not
  reproduce** (the transducer and mic don't share that rigid contact).
- **Beatrice self-stacking (output leaks back → re-converted → compounds): not observed.** On
  sustained singing the output stayed **stable and clean** — no gradual thickening / layering /
  runaway build-up over time, which is the tell-tale of self-stacking.

**Conclusion:** the bone-conduction-output + throat-mic loop **survives without self-stacking** in
informal testing. Test A's keystone risk is retired for the viva. Caveat: this is a **qualitative,
by-ear pilot**, not an instrumented gain-sweep with logged dB thresholds; if a hard number is wanted
for the writeup, redo with `level` telemetry logged while ramping output gain. The haptic-vibration
fallback (HARDWARE_ROADMAP §2) is no longer on the critical path but stays as a backup.

## Test B — perform-mode embodiment (DAEX) — through-tissue path **failed (predicted); committed to cup spatial source**
Tested the DAEX exciter pressed to the cheek (trying to radiate the choir via the oral cavity / body).
**Failed, as predicted by §3:** cheek flesh + fat absorb most of the structure-borne vibration
(soft-tissue damping), so the choir does not usefully radiate *through* the body. A **principled
negative result**, not a setback — it confirms the retracted "mouth-formant / through-body" claim.

**Decision (user):** the through-body sub-path is dead; **perform-mode commits to the cup
spatial-source design** — DAEX on a rigid cup at the mouth (validated 2026-06-24), where the cup is
the radiator and the choir reads as *spatially co-located with the singer* (a source at the mouth),
not literally radiating through tissue. **Future avenue: an electrolarynx-style exciter** (PhD §6),
which is designed to inject vibration that genuinely drives the vocal tract and so may achieve the
through-body excitation a surface exciter cannot. Updated HARDWARE_ROADMAP §7 Test B + the transducer
table; core thesis unaffected (the hero is the bone-conduction *learn* loop, Test A above).
