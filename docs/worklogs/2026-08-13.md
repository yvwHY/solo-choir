## §B 真正的發現：引擎的中文字串就是引擎↔shell 的通訊協定

做「全英文」時掃到 Python 端 54 筆使用者可見中文（會上 warn 條的 18、只進 log 面板的
36）。但關鍵不是數量——是 `app/respond_shell.py` 的 `_PATTERNS` **用中文在比對引擎
stdout**：

    ("listen", r"^聽…… *([\d.]+)s .*句 (\d+).*io (\d+)/(\d+)")
    ("render", r"^  收句→渲染…")
    ("phrase", r"^  句(\d+) .*回應 *([\d.]+)s .*開播 +([\d.]+)s.*靜音窗 +([\d.]+)s")
    ("bank_st", r"^音 (\S+) +cents +([+\-][\d.]+) +嘴 (開|閉) +xrun (\d+)")
    ("done", r"^共 (\d+) 句｜(.+)")   ("bank_on", r"^ready（音庫取樣器")

所以那些中文**不是顯示文字，是 wire format**。只翻引擎不改正則＝UI 狀態機（SING/HOLD/
RESPONSE 轉換、stats 欄位）全部失效但不會報錯——最壞的失敗形狀。我先只做 UI 層（零風
險）並把這個限制回報，Harry 裁「同步都改英文」，才做協定級改動。

**這條要記著：任何「引擎輸出格式」的改動都是雙邊改動。** 未來加欄位請接在**行尾**
（bank_live 的 v16/v17 註解已經有這個約定，v25 的 backlog 欄也照做＝正則的前綴不動）。

  `done` 狀態列只報句數（中文統計長句本來就只該待在 log 區）、`key` 欄位 trim。

做法：AST 精確定位每個 `print()` 的 span 整段置換（腳本 `en_migrate.py` 留在本次 session

不是字元偏移量**——用字元位置去切含中文的行會切壞後面的註解，第一版就這樣把語法弄壞，
還原重做才對。

## §G 五審查場（v24→v37）：Harry「這應該要是成熟的產品」

他回報「轉音會上下上下」→ dump 法醫：105s 內 95 次換音、**35% 是相鄰半音的 A→B→A**、

**三份 fresh 審查獨立判死那個死區**：生效機制是意外（夾住的幀被合理性門丟掉＝候選票
不清）、hys>0.5 會**永久卡音**（實測 5s 回不去剛離開的音）、0.55 起**靜默漏音**、且把
換音推到 0.3s 後＝滑音觸發率 46.6%→68.9%（貼近「有 autotune 就是不行」那條紅線）。
**v26 重做**：夾住的幀明講「他還在原來那個音」（走 `m == st["note"]` 分支清票）、上限
鎖 0.45（逃逸門檻 ≤0.95 < 鄰音中心 1.0 ⇒ 卡音與漏音結構上不可能）。實測：來回

同輪審查另外撈到兩個結構性遲鈍源與一個老 bug：**滑音其實是三階樓梯**（第一個 35ms
