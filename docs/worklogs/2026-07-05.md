## C. The big investigation — "why worse than vcclient?" (the day's spine)
Trigger: user re-ran `model/VC/dist` (vcclient) and found it noticeably cleaner than Solo Choir on the
**same engine + same trained models**. A controlled A/B ladder (offline renders, user-scored by ear,
5k model) nailed it:
- **Engine is fine.** `vc_probe` (one voice, pure conversion, static pitch, **direct callback, NO pump**)
  == vcclient by ear. Same Beatrice `.so` (md5-identical to vcclient's). The gap was never the engine.
- **The existing Solo mode's grit = `--pump`** (worker+ring, built for multi-voice; forced onto one
  voice with 4ms latency it manufactures underruns). vc_probe is clean because it's single-voice, no pump.
- **The harmony scrape = the dynamic pitch shift.** `set_pitch_shift_semitone` CHANGING per note scrapes
  the engine. Ladder: static/pure = 9; per-note jump (current) = 1; **glide 3–6¢/hop = 8 "接近9"**.
- **Decompiled vcclient 2.2.2** (PyInstaller-frozen → pyinstxtractor → `dis` bytecode): it sets pitch via
  batched `set_config` at UI-event rate in tiny cents, **never a per-block jump**; its clean slider-drag
  IS a fine glide. So glide == vcclient's actual mechanism, automated. All stream-mixing / chunk-recontext
  / SOLA approaches (V8–V14) DIED (Beatrice's per-stream phase is free-running → any crossfade blurs;
  re-fed context into the stateful stream = 10Hz tremor). 7→9 is bounded by the binding's ~5–10¢ pitch
  deadzone — needs a custom feature-domain binding (post-viva).

### Per-voice on/off (keep-warm) — `ced8c773`
Toggle each harmony voice. **OFF voices stay WARM** (converter + resampler still run each block) but aren't
summed → **no cold-resume zero-fill glitch on re-enable** (the "斷斷續續" pit from [[live-toggle-choppiness-fix]]).
Constant-power gain (`1/√n` over the ON count) keeps level steady as you toggle; all-off = silence.
User's explicit choice: keep-warm over save-CPU (CPU not saved, by design). Keys `on1..onN` in set_control.

### Model-switch desync bug — `94e8e78e`
User report: "換成男生模型、只開一部，卻聽到多個聲音；關掉全部聲部還是有聲音." Root cause: `set_model()`
rebuilds the engine; the fresh SoloEngine reset `voice_on`→all-True and `dry_on`→True, but the UI toggle
buttons kept their prior state → **UI showed 1 voice while the engine ran all 4.** Fix: carry the previous
engine's `voice_on`/`dry_on` onto the rebuilt one. Live-confirmed by user ("目前可以了").
- The "**關了所有聲部還是有聲音**" part was NOT the bug: **Dry You is an independent passthrough** — all
  harmony off still plays the raw voice unless Dry You is also off. By design (this is "You + choir").

### speaker 0/1 "換不了男女" — engine limit, not a bug
Offline A/B (5 WAVs rendered from a real vocal clip, in scratchpad `spk_ab/`) confirmed: speaker 0↔1 on
one voice **does** change the signal (max-abs-diff 0.38), but on a **male input** satb2's 0/1 is a
timbre nudge within male-ish range, **not a clean gender flip** — the documented [[beatrice-source-dependent-conversion]]
ceiling. Clean per-part gender needs offline-render-per-model or a true multi-speaker satb2 (post-viva).
