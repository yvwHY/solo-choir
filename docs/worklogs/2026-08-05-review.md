1. **高｜`respond2.py:596`｜實體鍵是死的**：開的是 UDP `TapListener`，定案路線是 USB serial（`main_usb.py` 只 print serial、WiFi 退場）；`SerialTapListener`（`tap_listen.py:88`）全 repo 無呼叫者。插 Pico 跑 live → 鍵 off、按了沒反應。真接上時 `:598` 存取 `tap.port` → Serial 版沒這屬性＝AttributeError。**＝STATE「respond2 接 tap」那格的實體內容，接線時一併修。**
2. **中｜`respond_shell.py:123`｜關視窗留孤兒引擎**：`_on_closed` 叫 `stop()` 即返回，8s 收屍執行緒是 daemon、行程結束就沒了，SIGKILL 永遠不送——而關流必卡 CoreAudio。修法：`_on_closed` 同步等 8s（dump 寫入實測 0.57s，安全）。
3. **中｜`respond2.py:609`｜out-map 解析太晚＋裸 ValueError**：排在模型載入後；UI map 欄打錯（如 `0,1,l`）→ 白等 10 秒再吐 traceback。把解析搬到 `build_ear_and_mouths` 前。
4. **中低｜`respond2.py:796`｜分路削峰警告口徑錯**：量逐聲道峰值，但 dump/耳朵是聲道總和（`:655`）；map 0,1,2 各 0.3/0.2/0.1 不告警、實際 0.6，`--gain` 建議值偏鬆。
5. **低｜`respond2.py:634`｜校準嗶聲全聲道廣播**：三喇叭同放 +9.5 dB（實測 dump 0.375 vs 0.125），開麥時是回授風險。改只送一個聲道或除以 n_out。
6. **低｜`respond2.py:754`｜dump 滿警告在閒置心跳裡**：連續唱不停的場永遠印不出來。搬出 `if not blocks` 分支。
